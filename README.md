# DevPulse Agent

Atlassian Forge app for Codegeist 2026 (Apps for Software Teams). DevPulse scans
pull request diffs for security patterns and surfaces the result in a Jira issue
panel and through a Rovo agent.

## Structure

```
src/
  index.ts                 Forge functions: Rovo action + UI resolvers
  actions/
    diffAnalyzer.ts        Pure unified-diff parser and risk scoring
    contextFetcher.ts      Jira issue history/related-issue enrichment
  frontend/
    index.tsx              UI Kit issue panel
  types.ts                 Shared TypeScript types
manifest.yml               Forge app manifest
```

## Getting started

1. Install dependencies:

   ```bash
   npm install
   ```

2. Replace the placeholder app ID in `manifest.yml` with the ARI generated by
   `forge register` (or by `forge create` if you scaffold a fresh app).

3. Typecheck, deploy and install:

   ```bash
   npm run typecheck
   forge deploy
   forge install
   ```

   Use `forge tunnel` for local iteration.

## Manifest notes

- The requested `entryPoint: main` is expressed in modern Forge as
  `resources[].key = main` plus `jira:issuePanel[].resource = main`.
- Two scope strings in the brief are not valid Forge scopes. This manifest uses
  their current equivalents:
  - `read:code:bitbucket` → `read:repository:bitbucket` and
    `read:pullrequest:bitbucket`
  - `read:confluence-content:summary` → `read:confluence-content.summary`
- A `rovo:agent` needs a `prompt` and an executable `action`, so the manifest
  also declares an `action` module that points at `rovo-action-resolver`, plus a
  second function module for the UI Kit resolver.

## Current behavior

- `runRovoAction` and `getDevPulseReport` analyze a supplied unified diff, or a
  deterministic mock diff when none is provided.
- `fetchIssueContext` queries Jira via `@forge/api` and falls back to mock data
  when the call fails or no issue key is available.
- `postReportToIssue` writes an ADF comment back to the Jira issue.
